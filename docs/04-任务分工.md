## 🔄 协作规范

### 开发流程
1. **每日站会**：上午9:30，同步进度和问题
2. **代码提交**：每天至少提交一次，按功能模块提交
3. **代码审查**：相互审查代码，架构师最终审核
4. **问题解决**：遇到问题2小时内无法解决，立即寻求帮助

### 代码提交规范
- 提交信息格式：`[类型]: 简要描述`
- 类型说明：
    - `feat`: 新功能
    - `fix`: 修复bug
    - `docs`: 文档更新
    - `style`: 代码格式调整
    - `refactor`: 代码重构
    - `test`: 测试相关
- 示例：`feat: 添加用户登录接口`

### 接口联调流程
1. 后端开发完成一个接口后，立即更新API文档
2. 前端根据API文档进行开发
3. 后端提供Postman测试集合
4. 前端按模块进行联调测试
5. 遇到问题及时沟通，记录解决方案

### 测试要求
- **单元测试**：每个Service方法都要有单元测试
- **接口测试**：每个API接口都要进行功能测试
- **集成测试**：前后端集成测试
- **用户验收测试**：最终用户场景测试

### 沟通渠道
- **技术问题**：GitHub Issues 或 团队群聊
- **进度同步**：每日站会 + 进度文档更新
- **重大决策**：全体会议讨论
